    Working principle, step by step

    Core idea

    Put anything that must be reachable from the internet in its own segment. If an attacker takes over a server there, the next firewall still stands between them and your internal data.

    Two layouts: a single firewall with three interfaces (internet, DMZ, LAN), or the more secure dual firewall (back-to-back) shown above, ideally from different vendors.

    Rules of the DMZ

    • Internet → DMZ: only the specific ports each service needs.
    • Internet → intranet: denied.
    • Intranet → DMZ: allowed, to manage servers and browse via proxy.
    • DMZ → intranet: denied, except narrow, logged exceptions such as web server to database on one port.
    • DMZ → internet: only replies and needed updates.
    1. Request arrives. A packet from the public internet (public IPs) reaches the outer firewall and NIPS 1.
    2. Outer filtering. The firewall checks IP, port and protocol against its ACL. The NIPS inspects the payload for known attacks and drops them.
    3. Delivery to a DMZ host. Only allowed traffic is routed to the public server (web on 80/443, mail on 25, bastion/VPN).
    4. Service handles it. The hardened server answers. If it needs data, it sends a narrow, logged query toward the inner firewall.
    5. Inner filtering. The inner firewall and NIPS 2 allow only that single flow (for example web server to database) and block all else.
    6. Internal users go out. Private IPs (via NAT) request external sites through a proxy or bastion host in the DMZ. The DMZ host opens the session outward.
    7. Replies return, nothing starts inward. The DMZ forwards only packets that were already requested; it cannot initiate a session into the private network.
    8. Monitor and log. NIDS sensors watch the segments and raise alerts to administrators or a SIEM; logs support incident response.

    Pros and cons

    Pros

    • Internal network is not directly exposed to the internet.
    • A compromised public server does not give automatic access to inside resources.
    • Fine-grained, per-zone access control and logging.
    • Easier to monitor: one place to watch exposed services.
    • Supports compliance (for example PCI DSS segmentation, NIST SP 800-41 guidance).
    • Enables safe partner access (extranet style).

    Cons

    • Extra cost: firewalls, IPS/IDS, servers and licenses.
    • More complex design, rules and maintenance; misconfiguration can create holes.
    • Does not stop insider threats or attacks hidden in allowed traffic.
    • The DMZ itself is a target and needs patching and hardening.
    • Encrypted traffic limits inspection unless TLS is terminated.
    • Added latency and a possible single point of failure without redundancy.
